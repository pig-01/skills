# Step Up

協助使用者準備一個可開始工作的專案目錄。這是精簡的起始範例，可依專案需求擴充。

## 選定工作目錄

使用使用者指定的路徑；未指定時使用目前工作目錄。若目前工作目錄無法取得，先詢問目標路徑。以目標資料夾名稱作為預設專案名稱。

先確認目錄是否存在，讀取適用的專案指示，並檢查現有 README、忽略規則與目錄結構。有既有專案時沿用它的結構，只補齊本次要求的項目。

## 建立起始結構

對新的或空白的工作目錄建立：

```text
<project>/
├── README.md
├── .gitignore
├── src/
└── docs/
```

- `README.md`：寫入專案名稱、已知用途與目錄說明。未提供用途時標示「待補充」，不要推測技術框架或執行指令。
- `.gitignore`：先加入 `.DS_Store`、`Thumbs.db`、`.env`、`.env.*` 與 `!.env.example`；已有明確技術棧時再補上對應的產物與快取規則。
- `src/`：放置原始碼。
- `docs/`：放置專案文件。

保留已有檔案的內容。若需要補充現有忽略規則，先確認規則尚未存在再追加；使用者未要求整理的現有專案不套用新目錄結構。使用者要求將空資料夾納入 Git 時，再以 `.gitkeep` 保留。

此範例只初始化檔案與資料夾。安裝依賴、初始化 Git、建立 commit 或推送遠端，依使用者另外提出的需求處理。

## 確認結果

列出目標目錄，確認本次應建立的檔案與資料夾存在。簡短回報實際路徑、新增或補充的項目，以及需要使用者填寫的資訊。只有目錄初始化完成才能回報完成；不要將它描述為已能執行的應用程式。
